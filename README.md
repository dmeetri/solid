# SOLID

SOLID — российская внутренняя система для создания и приёма заявок от сотрудников и подразделений компании.

# Запуск проекта

Данная инструкция подробно описывает каждый шаг от установки до запуска проекта на сервере, указывая все возможные ошибки, которые могут появиться в процессе эксплуатации

Запуск и настройка проекта описывает способ без использования систем контейнеризации таких как Docker. При желании вы можете запустить проект используя контейнеры, что не повлияет на работу самого приложения

Вся инструкция описывает запуск проекта с использованием ОС Linux

## Подготовка сервера

Для полноценной работы проекта на сервер необходимо установить `Python`, а так же веб сервер. В данной инструкции описывается работа с `Nginx`, тк он является стандартом веб разработки и находится в разрешенном списке БДУ ФСТЭК России

[Ссылка на Nginx БДУ ФСТЭК России](https://bdu.fstec.ru/search?q=nginx)

### Установка и подготовка Python

Python необходим для работы на сервере, тк весь проект написан с использованием данного языка программирования. По умолчанию Linux уже имеет все необходимое для работы. Если это не так, можно вписать команды ниже. Данные действия ни как не повлияют на сервер

```
# Обновим список пакетов
sudo apt update

# Установка Python
sudo apt install python3 -y

# Установим менеджер пакетов и виртуальное окружение. Без него установить зависимости для проекта будет невозможно
sudo apt install python3-pip python3-venv -y

# Проверяем версию Python
python --version
```

### Установка и подготовка Nginx

Nginx - это веб-сервер, который будет принимать все запросы к проекту, а так же управлять переадресацией на ssl, для защиты информации. Если пропустить данный шаг

Если в шаге выше вы не прописывали данную команду `sudo apt update`, то стоит ее прописать, чтобы обновить пакеты сервера

```
# Установливаем Nginx
sudo apt install nginx

# Запускаем сервис
sudo systemctl start nginx

# Проверяем статус
sudo systemctl status nginx

# После данной команды в терминале вы увидите зеленую надпись enable. Если все прошло успешно
# Если после установки nginx не запустился сам, просто запустите его в ручную
# Данную команду можно прописать, даже если nginx запущен. Вам просто выведет сообщение о том, что сервис уже находится в работе
sudo systemctl start nginx

# Добавляем в автозагрузку, чтобы при перезапуске сервера nginx запускался вместе с ним
sudo systemctl enable nginx
```

> [!WARNING]
> Убедитесь, что на сервере открыты нужные порты. На данном этапе важны 443 - используется для защищенного трафика и 80 - обычный трафик с которого принимаются запросы и передаются на 443 автоматически

## Установка проекта

Все файлы проекта устанавливаем в `/var/www/`. Тк проект уже имеет корневой репозиторий, ничего создавать не нужно. Просто перенесите все файлы в данную директорию

После того, как все файлы проекта находятся в нужной директории, необходимо перейти в нее и создать окружение, в котором будет работать приложение

```
# Переходим в директорию
cd /var/www/solid

# Создаем виртуальное окружение
python3 -m venv venv

# Активируем окружение. В терминале вы увидите приписку (venv)
source venv/bin/activate

# Устанавливаем зависимости проекта
pip install -r requirements.txt
```

## Настройка проекта

Когда сервер полностью настроен и готов к работе вам необходимо подготовить проект для его работы. Ниже описаны все действия для подключения базы данных и базовой настройки проекта

### Подключение базы данных

Для начала определимся с базой данных. Для этого есть два способа. Первый самый простой и подойдет для малых организаций. Использовать его не рекомендуется. Отлично подходит для тестов. Второй способ правильный и подойдет для всех случаев

#### Первый способ

Первый вариант использует встроенную базу данных SQLite. Разворачивать данную базу не нужно, она уже встроена и используется по умолчанию. Если вы выбрали данный способ, то ничего делать не нужно. Смело переходите в раздел `Применяем миграции` ниже

Важно понимать, что такая база данных храниться прямо на сервере, в том же пространстве, что и само приложение и не рекомендуется для готовго решения

#### Второй способ

Второй способ подразумаевает использование базы данных PostgreSQL. Данная инструкция не объясняет, как развернуть базу данных, а только показывает подключение к уже существующей базе

В процессе написания

#### Применяем миграции

После того, как вы выбрали базу данных и подключили ее, необходимо применить миграции

```
# Переходим в папку проекта, в которой лежит manage.py
cd solid

# Проверяем, что мы находимся в нужной директории
# В списке вы должны увидеть файл manage.py
ls

# Создадим миграции для базы данных
python manage.py makemigrations

# Применяем миграции в базу данных
python manage.py migrate
```
